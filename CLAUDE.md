# CLAUDE.md
@README.md

Kraftvakt is a Home Assistant custom integration that keeps the average consumption over the last hour just below 
a power limit (the Norwegian capacity tariff), by turning appliances and EV chargers on and off in priority order.

Python integration in `custom_components/kraftvakt/`, 
panel in `frontend/` (Lit + TypeScript, committed bundle), 
tests in `tests/`.

## Skills
Read the skill for the kind of task before starting:
- `kraftvakt-regulation`: how the regulation must behave, and every rule settled with the owner. The specification of the integration.
- `kraftvakt-backend`: modules, stored configuration, validation, actions, entities and the WebSocket API.
- `kraftvakt-panel`: the panel, the HA components it may use, and the build.
- `kraftvakt-testing`: test layout and conventions, checks before commit, and manual testing against a local Home Assistant.
- `kraftvakt-simulator`: the simulated HAN, heaters and EV chargers for local testing, and how to write code for them.

## Behavioral Guidelines
- Always create a branch from main for a new session, commit when tasks are completed, never push, never merge to main.
- Ask for input and guidance when in doubt.
- Don't make own decisions when in doubt, ask.
- Always ask when you find the behaviour described in the skills ambiguous or in need of clarification. Same goes for user prompts.
- If a skill, or user prompt, goes against any statement in this file; handle it as ambiguous.
- When the owner settles a question about behaviour, record it in the skill it belongs to.

## Documentation Rules
- The README.md file is for users of the integration and for developers. Keep the information up to date with the code.
- All documentation shall be written in English. Do not edit this file, only suggest changes.
- Do not write documentation that will need update for every code change. Do not use fragment from code as examples, or number of tests, current coverage etc. Generalize instead.
- All decisions and information that is important for the next coding session, and to understand the code easier, shall be documented in the skill files.

## Coding Rules
- Write readable code that human beings can read and understand.
- Let the code speak for itself through naming, not comments.
- Write as little comments as possible and only for important decisions and docstrings for every public method.
- Focus on separation of concerns to make the code adaptable to changed requirements.
- Avoid specific code for each problem, lean on generic solutions, as long as the code is still understandable.
- Follow Home Assistant coding standards and principles for integrations.
- All code and commit messages shall be written in English, except translation files.
- When finished with a coding task, review your own code and verify the rules in this file and the related skills for the task is followed.

## Test code rules
- When writing test code, the coding rules also applies.
- Focus on black box testing (HA test harness), they tend to find more faults than unit tests.
- Focus on code coverage when writing tests, not every possible permutation.
- Fault handling, and other code, that is hard to get coverage for using black box testing - shall be tested with unit tests.
- Isolate complex logic into testable units with unit test to prove the logic by itself,
  then use black box testing to verify the logic working together with the rest of the code base as intended.
- Every commit passes the checks in the `kraftvakt-testing` skill.
